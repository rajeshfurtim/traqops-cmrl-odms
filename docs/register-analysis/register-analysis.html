Key findings

Scope

23 registers in the menu. Three groups: train operations & safety (10, several OCC- or department-driven), station services (8), and Last Mile Connectivity (5). They are not one kind of thing: some are simple station logs, others are multi-party permit workflows.

Pattern

Almost every register uses the same page shell: title + station, KPI tiles that filter the table, a Filter panel, Copy/Excel/CSV/PDF/Print, a data table and row actions. Most records open as an official CMRL form (Doc no, Rev, Date) with a timeline, images and a "Sign & metadata" block. These become shared components.

Pattern

Official forms found: Caution Order CMRL/OPER/SO/F-43, Passenger Assistance F-33, Manual Point F-32, Mock Drill F-28, Incident CMRL/OPER/SO/R4, OCC Event Report DOC_OCC R-04, TSR application (Special Instruction No. 07 to MRGR 2013). Assurance has an ISO Document Setting (document name, display name, ISO number, revision, date) — the same idea as our export header template.

Whole app

The rest of the old system was captured too (28/09): Dashboard, Manuals, PN Book, Employee Operations, EPIC list, Lost & Found, ~50 Masters, PTW, WGO, Customer Care, Station Diary and Asset — see Whole-application discovery. Five routes are 403 for this login and two crash with server errors.

Gap

Create forms were hidden for this account on most registers (no Add button, or 403 "User does not have the right permissions"). I captured create forms fully only for Incident and LMC Marketing; for the rest, fields are inferred from columns and record views. An account with create/approve rights (or the paper forms) is needed to close this.

Login

The old login also asks for Station (56 options) and Shift after the employee ID. Our new login does not yet. Shift names also differ: register filters use A, B, C, Evening, General while ODMS uses A, G, B, C.

Security

The live site runs with Laravel debug mode on. Two pages (a guessed /imprest/create and the Metro Connect menu page, which crashes) showed source code, SQL queries and the session cookie. This should be reported to the old system's maintainers (APP_DEBUG=false). Signing out of cmrl-odms.com ends the exposed session.

Caution Order

Train operationsCMRL/OPER/SO/F-43 · Rev 01

Temporary restrictions (speed, mode, direction) between two stations, issued to every train set that runs through. The SC hands each train operator a copy and uploads the acknowledged copy.

List
KPI tiles: Total, Completed, Active, Pending, Frozen, Cancelled, Pending cancel, Expired, Today orders, Today permits, Issued started. Columns: Order ID (2026/0003/STST-SWD/OPN = year/seq/from-to/dept), Date, From–To, Department, Trains (count and breakdown), Issued (count, train nos), Direction, Mode, Speed, Mast nos, Time (start / E.O.S), Reason, Status, Action.
Filters
Text; Direction (UP/DOWN/BOTH); Mode (ATO/ATP/CUT OUT/RM); Department (20); Issue progress (pending / all issued); Status; Date from–to; Speed min–max.
Create
Not at station level. Orders are raised centrally (OCC/department). Create form not seen.
View / print
Official form "Caution Order (Train Operator / SC copy)": date, ref no, form no (2026/STST/00003), train set no, instruction text with reason and department, validity (from time till End of Service), restrictions table (station from/to, line, direction, mast from/to, speed, permitted mode), OCC cancellation clause (via TETRA), issued by SC (name, emp no, time, signature), TO acknowledgement (name, emp no, time of receipt, signature). Print.
Workflow
Pending→Active→Completed/Expired/Frozen/Pending cancel→Cancelled. "Till End of Service" validity.
Actions
Per train set: issue + upload signed copy; "Completed" when every train is issued.
Attachments
Uploaded signed permit per train (Permits page: Issue date, Form no, Order ID, Train set, From–To, Dept, Upload status, Document).
Relationships
Masters › Mode of operations; Stations; Departments; Quick Links.

Create

View / print

Workflow

Relationships

Common patterns

Register page

  • Title + station code; KPI tiles that filter the table ("KPI view").
  • Filter panel: date range, status, type, department, shift, free text.
  • Copy · Excel · CSV · PDF · Print; page size up to All.
  • Row actions: View, ⋮ Edit / Delete; bulk select on a few.
  • Quick Links to related masters and registers.

Record view = official form

  • Header: CMRL, form title, Doc no, Rev, Date.
  • Sections of label/value pairs.
  • Repeating timeline (date, time, action/observation).
  • Attached images.
  • Sign & metadata: submitted by/at, revision at, revision no, date of record, place, signature of SC/SI.

Forms

  • Auto reference numbers per register (station, year, dept, sequence).
  • Dependent selects (class → sub-class).
  • Yes/No questions that open a required details field.
  • Count matrices (gender × in/out/interchange).
  • Computed values: time taken (across midnight), days parked, charges.
  • Private number (PN) fields for OCC coordination.

Workflows

  • Request → approve / reject (Key, Cab Pass, PTW, WGO).
  • Two-level approval (HOD → OP-HOD).
  • Issue → extend → cancel (TSR, PTW, Caution Order).
  • Schedule → execute → review → approve (Mock drill).
  • Open → attend → rectify → close (LMC faults).
  • Pending → finalised & locked (TTM).

Old-system defects not to carry over

Security

Debug error pages expose source, SQL and session cookies. The new app must never show internal errors to users.

Bug

Metro Connect page crashes on a missing master record; WGO shows raw IDs instead of names.

Rules

WGO allows bulk delete; our rule is that register records are never deleted (cancel or void with a reason instead).

Usability

Buttons shown to users who lack the permission (Add Entry → 403). New app: hide or disable with a reason.

Consistency

Shift names differ between screens (A/B/C/Evening/General vs A/G/B/C); date formats vary (2026-09-17, 17-09-2026, 17 Sep 2026) and some rows show only a time. New app: 24/09/2026 14:58 everywhere.

Performance

Some pages load every station's records at once. New app: filter by station and paginate on the server.

Validation

Incident says the timeline is optional but also requires one row. Rules must be stated once, in the definition.

Proposed approach (for your decision)

One register engine driven by configuration covers most registers. A few need their own screens built from the same parts.

Config-driven (engine)

Passenger Assistance, Essential Equipment, Incident, Manual Point Operation, Local Traffic Regulation, Mock Drill (station side), Parking, PD Management, Key Register, LMC Asset Fault, LMC Audit, LMC Trip Sheet, Metro Connect.

Custom screens on shared parts

Caution Order (per-train issue), TSR + Signaling, Possession/PTW, WGO, Train Traffic (OCC), Cab Pass (two-level approval, printing), Imprest (cash flow), Assurance (reading gate), LMC Marketing (project tracker), Mock Drill scheduling/review.

Suggested phases

  • Phase 1: engine upgrade (field types, official record view, workflow, masters) + station registers: Incident, Passenger Assistance, Essential Equipment, Manual Point, LTR, Key, Parking, PD, Mock Drill (station).
  • Phase 2: permit and approval registers: Caution Order, TSR/Signaling, Possession/PTW, WGO, Cab Pass, Imprest.
  • Phase 3: LMC group, Assurance, Train Traffic, analytics.
  • Replace the current placeholder registers in the new app (Occurrence Log, Safety Inspection, Fire Drill, Equipment Fault, Keys, Complaints, Lost & Found) with the real ones above.
